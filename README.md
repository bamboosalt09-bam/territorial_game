# territorial_game

모바일 브라우저용 실시간 영토 전략 게임.

Territorial.io 식의 단순한 조작(상대를 탭하고 공격 / Balance 비율 선택)을 유지하면서,
**도시 · 수도 · 방어기지 · 참호 · 해상 상륙 / 해상 요격** 만 최소한으로 더했다.

빌드 도구 없음. ES modules + Canvas 2D 만 쓴다.

---

## 실행

정적 파일이지만 ES modules 를 쓰므로 `file://` 로는 열리지 않는다. 로컬 서버가 필요하다.

```bash
npx serve .
```

그 다음 브라우저에서 `http://localhost:3000` 을 연다.

검증 테스트 (DOM 없이 Node 에서 실행):

```bash
node tests/front.test.mjs
```

```bash
node tests/balance.test.mjs
```

`front.test.mjs` 는 전선 알고리즘이 맞는지, `balance.test.mjs` 는 실제로 한 판이 성립하는지 본다.
후자는 전체 시뮬레이션을 돌리므로 1분 남짓 걸린다.

## 조작

| 대상 | 표시되는 행동 |
|---|---|
| 상대 일반 땅 | 공격 / 화친 |
| 상대 해안 | 배 / 공격 / 화친 |
| 중립 땅 | 확장 |
| 적 함선 | 배 (요격) |
| 내 땅 | 정보만 |

- 한 손가락 드래그 = 지도 이동, 두 손가락 = 확대/축소, 짧은 탭 = 선택
- 하단 슬라이더로 현재 Balance 중 몇 %를 투입할지 정한다
- **공격 방향은 지정하지 않는다.** 대상 국가만 고르면 두 나라가 공유하는 국경 전체가 전선이 된다
- 육상 국경이 없는 상대는 공격 버튼이 비활성화된다
- 배는 **목표 해안만** 지정한다. 출발 해안은 가장 가까운 자국 해안이 자동 선택된다
- 참호는 버튼을 켠 뒤 자기 영토 위를 드래그하면 미리보기 선과 비용이 뜬다

## 규칙 요약

### 지형
물과 땅, 두 종류뿐이다. 산악 · 숲 · 강 · 도로 · 이동력 보정 같은 것은 없다.
도시 / 수도 / 방어기지 / 참호는 지형이 아니라 땅 위에 올라가는 별도 레이어다.

### Balance
경제와 군사가 하나의 자원으로 통합돼 있다. 육상 공격, 해상 출항, 건설이 모두 Balance 를 쓴다.
영토와 도시가 정하는 상한을 향해 점근하도록 성장하므로, 쌓아 두기만 해서는 늘지 않는다.

### 전투
국가별 공격력 / 방어력 / HP 스탯은 없다. 전투력은 Balance 와 영토 면적에서만 나온다.

```
defenseDensity = defenderBalance / defenderLandCells      (하한 있음)
captureCost    = 2 * defenseDensity * (1 + trenchBonus + fortBonus)
defenderBalance -= defenseDensity                          (셀 하나당)
```

같은 Balance 라도 영토가 넓으면 밀도가 낮아 전선이 쉽게 밀린다.
셀을 뺏길 때 밀도가 그대로 유지되도록 설계돼 있어, 점령이 진행돼도 교환비가 급변하지 않는다.

### 시설

| 시설 | 비용 | 효과 |
|---|---|---|
| 수도 | 건설 불가 (시작 도시가 수도) | 소득 +20%. 뺏기면 효과만 잃고 국가는 유지된다 |
| 도시 | 지을수록 상승 (`base * 1.22^n`) | Balance 상한과 소득 증가 |
| 방어기지 | 고정 | 반경 안의 자국 셀 점령 비용 +45%, 전선도 느려짐 |
| 참호 | 길이 비례 (`length * unit`) | 그 선을 **넘는** 공격의 점령 비용 +30%, 전선 지연 |

### 해상
별도 해군 경제는 없다. "배"는 공격 Balance 를 바다로 옮기는 수단이다.
함선 종류 · 생산소 · 유지비 · 항구 건설은 없다.

- 항해 중 병력이 아주 조금씩 지수 감쇠한다. **자연 감쇠만으로는 절대 0 이 되지 않는다** (하한 1)
- 전투로 전멸하는 것은 별개이며 가능하다
- **상륙 추가 페널티 없음.** 도착하면 육상과 완전히 같은 식으로 계산한다
- 상륙 성공 시 교두보가 생기고, 남은 병력은 그대로 육상 공격으로 이어진다
- 해상전은 `loss = min(A, B)` 로 서로 상쇄하고 남은 쪽이 생존한다
- 요격 승리 후 남은 함대는 자국 해안으로 귀환하고 병력이 Balance 로 돌아온다

### AI
쉬움 / 보통 / 어려움 / 매우 어려움, 네 단계.
자원 치트는 주지 않는다. **판단 품질만** 차등화한다:
판단 주기, 점수 노이즈, 투입 비율 오차, 해상 공격 / 요격 / 시설 사용 빈도,
다면전 노출 평가 여부(어려움 이상), 짧은 lookahead(매우 어려움).

## 핵심 알고리즘

### 육상 전선 — shape-preserving wavefront

이 프로젝트에서 가장 중요한 부분이다.

공격이 시작되면 **수비국 셀 중 공격국 셀과 변을 공유하는 모든 셀**을 동시에 seed 로 넣고,
가중 wavefront(우선순위 큐 기반 Dijkstra 형)를 점진적으로 확장한다.

한 점이 아니라 국경선 전체가 출발선이므로, 등거리 집합은 그 국경선의 offset curve 가 된다.
그래서 **굽은 국경은 굽은 형태 그대로 전진한다.**

| 요소 | 처리 |
|---|---|
| 격자 왜곡 | 직교 1, 대각 √2. 접경 판정만 4방향, 내부 거리는 8방향 |
| 방향 순서 편향 | 같은 거리 밴드(0.35)를 묶어 결정론적 해시로 섞어 처리 |
| 계단 현상 | step 마다 아주 작은 결정론적 노이즈 |
| 전투량 vs 속도 | budget 과 `visibleFrontSpeed` 를 완전히 분리. 큰 공격도 순간이동하지 않는다 |
| 동시 공격 | 한 tick 에 모든 공격이 proposal 만 만들고, 셀 충돌을 판정한 뒤 일괄 반영 |
| 지도 변화 | 전체 distance map 을 미리 계산하지 않고 큐에서 필요한 만큼만 점진 확장 |
| 포위 | 별도 포위 보너스 없음. 공유 국경 전체가 seed 라 자연히 사방에서 압축된다 |

`maxCellsPerTick` 안전판이 있어 모바일에서 한 프레임이 폭주하지 않는다.

### 참호 — edge 기반

참호는 "참호가 있는 셀"이 아니라 **셀과 셀 사이의 edge** 에 저장한다.

```
trenchH[y*W + x] : 셀 (x, y-1) 와 (x, y) 사이의 가로 edge
trenchV[y*W + x] : 셀 (x-1, y) 와 (x, y) 사이의 세로 edge
```

플레이어가 그린 선은 격자 꼭짓점(래티스) 좌표로 스냅되어 계단형 단위 스텝으로 래스터화된다.
**그린 선 자체가 방벽**이 되고, 그 선을 넘는 공격만 페널티를 받는다.
참호 뒤로 들어간 뒤에는 보너스가 붙지 않는다.

효과는 두 갈래로 나뉜다.
- `defenseBonus` → 점령 Balance 비용 배율 (문서의 `captureCost *= 1.25`)
- `frontDelay` → 그 edge 를 넘을 때 전선 거리에 더해지는 값 = 눈에 보이는 지연 깊이

두 값을 분리해야 "참호 구간만 눈에 띄게 늦게 밀린다"는 요구와 "비용이 오른다"는 요구를
각각 독립적으로 조절할 수 있다.

### 해상 경로 — multi-source

플레이어가 목표 해안만 고르므로, 자국의 모든 해안에 붙은 물 셀을 **동시에** 출발점으로 넣는
multi-source Dijkstra 를 한 번만 돌린다. 그러면 "가장 가까운 자국 해안"과 "최단 해상 경로"가
한 번에 나온다. 자국 해안마다 A* 를 반복할 필요가 없다.

대각 이동은 양옆이 모두 물일 때만 허용해 육지 모서리를 뚫지 않는다.

**"배를 보낼 수 있는가"** 판정은 경로 탐색을 돌리지 않는다.
지형은 게임 중 바뀌지 않으므로 물 연결 성분을 한 번만 계산해 두고 성분 비교로 O(1) 에 답한다.
UI 가 매 프레임 Dijkstra 를 도는 일을 막는다. 실제 항로는 출항하는 순간에만 계산한다.

### 요격
요격함은 `targetFleetId` 를 들고 다니며 0.35초마다 현재 위치 기준으로 경로를 다시 계산한다.
매 프레임 전체 탐색을 돌리지 않는다.

```
  ai/AIController.js     Utility AI, 난이도별 판단 품질
  ui/                    Camera, Input(팬/핀치/탭/드래그), HUD

  front.test.mjs       인수인계 23장 전선/해상 검증 케이스
  balance.test.mjs     초반 안정성, 난이도 격차, 죽음의 나선 방지
```

### 성능 메모
- 모든 지도 레이어는 typed array
- 지도는 셀 1개 = 픽셀 1개인 오프스크린 캔버스에 그린 뒤 확대. **소유권이 바뀐 셀만 패치**한다
- 국경 재계산은 0.2초 주기이며, 소유권이 하나도 안 바뀌었으면 건너뛴다
- AI 는 난이도별 0.35~2.6초 주기이고 서로 겹치지 않도록 jitter 를 준다
- 참호는 설치된 edge 목록만 따로 들고 있어 렌더러가 전체 배열을 훑지 않는다

측정치(384×240 지도, 7개국 교전 중): tick 약 0.8ms, render 약 0.35ms.

## 검증

`node tests/front.test.mjs` 가 인수인계 문서 23장의 케이스를 그대로 확인한다.

- 직선 국경이 균일하게 전진 (전진량 표준편차 < 평균의 35%)
- 굽은 국경이 곡률을 유지하며 이동
- 좁은 전선은 깊게, 넓은 전선은 얕게 (같은 예산에서 10배 차이)
- 포위 시 별도 보너스 없이 사방 균등 압축
- 참호 절반 구간에서 돌출부 형성 / 측면 우회가 더 빠름
- 참호가 edge 레이어에만 기록됨
- 방어기지 영향권 안이 더 느리게 밀림 / 점령 시 보너스 이전
- 해상: 최근접 자국 해안 자동 선택, 섬 우회, 경로 없음 판정
- 항해 감쇠가 1시간 뒤에도 0 이 되지 않음
- 상륙 비용 = 육상 비용 (추가 페널티 없음)
- 해상전 `loss = min(A,B)`, 귀환 병력 Balance 복귀
- 비접경 공격 차단 시 Balance 미소모
- 동시 공격 편향 없음 (좌우 대칭 시나리오에서 100% 일치)
- 큰 공격도 전선 속도 제한을 넘지 않음

`balance.test.mjs` 는 시드 8개를 실제로 돌려 다음을 확인한다.

- 개전 45초 안에 멸망하는 국가가 없다 (방치한 플레이어 포함)
- 개전 40초 안에 AI 해상 원정이 없다 — 근처 중립 땅이 남았는데 원정을 나가지 않는다
- Balance 가 바닥난 나라도 셀당 최소 비용을 요구한다 (작은 상륙 하나로 대국이 쓸려나가지 않는다)
- 난이도가 올라갈수록 AI 가 실제로 지도를 더 많이 먹는다 (180초 기준 65% → 72% → 81% → 87%)
- 난이도가 AI 의 소득 / 상한 / 시작 Balance 를 바꾸지 않는다 (자원 치트 없음)
- 240초 안에 지도 대부분이 점유된다 (교착 없음)

## 아직 확정되지 않은 수치

인수인계 문서 31장이 "미확정"으로 남긴 항목들이다. 전부 `src/config.js` 한 곳에 모여 있으므로
플레이 감각을 보면서 조절하면 된다. 현재 값은 합리적인 초기값이며 확정된 기획이 아니다.

- Balance 성장 계수, 도시 1개당 효과, 수도 보너스(현재 소득 +20%)
- 도시 기본 비용 / 증가율, 방어기지 비용 / 배율 / 반경
- 참호 단위 비용 / 방어 배율 / 전선 지연
- 기본 공격 비율, 함대 출항 비율, 감쇠 계수 `k`
- 화친 수락 규칙과 지속 시간 (현재 최소 구현)
- 맵 크기 / AI 수 / 승리 조건 지분 (현재 70%)
